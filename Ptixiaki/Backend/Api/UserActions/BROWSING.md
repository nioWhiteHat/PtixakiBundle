# Property browsing endpoints

Both routes are GET-only and use the existing `auth.Authenticate` cookie wrapper.
Restart the Go server after rebuilding. No database migration, new dependency,
Python call or training is needed for these routes. The Browse frontend uses them.

## Browse: `/User/BrowseProperties`

The frontend uses `/analysis/autocomplete?q=...` as before, then sends the
selected suggestion's coordinates, not the area name. The autocomplete
`boundingbox` array is ordered **min latitude, max latitude, min longitude,
max longitude**; map those strings to the four named query parameters below.

| Query parameter | Meaning |
| --- | --- |
| `min_lat`, `max_lat`, `min_lon`, `max_lon` | Optional bounding box in degrees; omit all four to browse all areas, or supply all four |
| `transaction` | `sell` or `rent`; defaults to `sell` |
| `index` | One-based page number; defaults to `1` |
| `construction_year_min`, `construction_year_max` | Optional inclusive year bounds |
| `renovation_year_min`, `renovation_year_max` | Optional inclusive year bounds |
| `estimated_price_per_sqm_min`, `estimated_price_per_sqm_max` | Optional inclusive estimate bounds, EUR/m² (rent uses the stored rental price unit) |
| `elo_min`, `elo_max` | Optional inclusive Elo bounds |
| `asking_price_per_sqm_min`, `asking_price_per_sqm_max` | Optional inclusive asking bounds, EUR/m²; same value as the overview |
| `square_meters_min`, `square_meters_max` | Optional inclusive size bounds, integer m² |

You may send either bound or both. Leave unused filters out. All supplied
filters combine with AND; a missing database value cannot match a range.
An inverted filter range simply returns no matches. Years, size and Elo are integers;
asking and estimated prices may contain decimals.

Results cover residence apartments, detached houses, and maisonettes throughout
the dataset, including user-added properties, not just the current portfolio.
No owner identity, credentials, or user-to-property links are returned. The new
read access is deliberately broader than the existing owner-only detail route.

Ordering is `elo DESC NULLS LAST, uid ASC`. Pagination is exactly
`OFFSET (index - 1) * 20`. The query reads at most 21 rows, returns at most 20,
and sets `has_next` when the extra row exists. This avoids an extra empty page
at the end without running a total-count query. Past the end, `properties` is `[]`.

Each overview includes UID, estimate/asking per m², square metres, address,
Elo, GeoPremium, construction/renovation years, and one image. The image is a
URL or a base64 data URL, or explicitly `null` for the frontend's SVG fallback.
Missing other overview values stay `null`, never fabricated as zero. Asking
falls back to stored total asking divided by area if its per-m² value is absent.

Illustrative response (synthetic values):

```json
{
  "index": 1,
  "page_size": 20,
  "has_next": false,
  "properties": [
    {
      "uid": "property_example",
      "estimated_price_per_sqm": 3200.5,
      "asking_price_per_sqm": 2650,
      "square_meters": 82,
      "address": "Example address",
      "elo": 11500,
      "geo_premium": 18,
      "image": null,
      "construction_year": 2004,
      "renovation_year": 2019
    }
  ]
}
```

PowerShell example, run from the directory containing your existing cookie file
(the example box is around Piraeus; normally use the autocomplete result):

```powershell
curl.exe --fail-with-body -b .\cookie.txt "http://localhost:8080/User/BrowseProperties?min_lat=37.90&max_lat=38.02&min_lon=23.55&max_lon=23.70&transaction=sell&index=1&asking_price_per_sqm_min=1000&asking_price_per_sqm_max=2000&square_meters_min=50&square_meters_max=100"
```

## Open a result: `/User/BrowseProperty?uid=...`

Use the UID returned by browsing:

```powershell
curl.exe --fail-with-body -b .\cookie.txt "http://localhost:8080/User/BrowseProperty?uid=PROPERTY_UID_FROM_RESULTS"
```

This reuses the existing `PropertyDetails` reader: stored input features,
estimate/asking per m² and totals, Elo, GeoPremium and its z-score, residual,
stored SHAP explanation and signed contributions/local percentages, and global
feature importance. It reads a consistent, read-only database snapshot. Missing
SHAP stays `explanation: null`; no explanation is generated by reading a property.
Unknown asking remains omitted as in the original detail contract. The only JSON
shape difference is that a missing image is explicitly `image: null`.

It does not require portfolio ownership. Missing or unsupported properties
return 404. `/User/ViewProperty` still requires ownership and otherwise retains
its existing GET/legacy POST contract. Neither route changes property data.

## Verification

From the `Ptixiaki` Go directory:

```powershell
go test ./...
```

The browse tests cover parameterized filters, bbox ordering, page offsets,
overview mapping, URL/binary/null images, empty pages, HTTP errors, auth
rejection, non-owner browse details, and retained owner-only portfolio behavior.

For an optional **read-only** integration test against the configured database:

```powershell
$env:BROWSE_LIVE_DB_TEST = "1"
go test ./Backend/Api/UserActions -run '^TestBrowsePropertiesLiveDatabase$' -count=1 -timeout=60s -v
Remove-Item Env:BROWSE_LIVE_DB_TEST
```

The live test checks sell/rent pages, `has_next`, all-area defaults, detail readers
and all six combined inclusive filters. It does not create or delete fixtures and expects an existing
populated database with the explanation schema installed.
