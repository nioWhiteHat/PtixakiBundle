# 8. Backend, αιτήματα χρήστη και ανάλυση περιοχής
## 8.1 Authentication και όρια πρόσβασης
Οι διαδρομές /User και /analysis τυλίγονται με το υπάρχον AuthMiddleware. Η λογική διαβάζει JWT από cookie, επικυρώνει την υπογραφή και τοποθετεί το user_uid στο context. Ο handler δεν πρέπει να εμπιστεύεται UID χρήστη που θα έστελνε ο browser μέσα στο JSON. Το context λειτουργεί ως εσωτερική μεταφορά της ταυτότητας που έχει ελέγξει το middleware. Η αυθεντικοποίηση απαντά ποιος είναι ο χρήστης· ο έλεγχος ιδιοκτησίας απαντά τι δικαιούται να διαβάσει ή να αφαιρέσει.

Το SignIn ελέγχει αποθηκευμένο bcrypt hash. Το cookie έχει HttpOnly, Secure και SameSite ρυθμίσεις. Αυτό δεν αρκεί για παραγωγική ασφάλεια. Στο υπάρχον έργο υπάρχουν ενσωματωμένα μυστικά, signup-controlled admin flag και απροστάτευτες διαδρομές συντήρησης. Τα μυστικά δεν παρατίθενται στην εργασία. Πριν από οποιαδήποτε δημόσια έκθεση απαιτούνται αντικατάσταση και περιστροφή τους, περιβαλλοντική διαμόρφωση, ασφαλής σύνδεση βάσης και σαφής πολιτική εξουσιοδότησης.

Η public ως προς τους συνδεδεμένους χρήστες BrowseProperty επιτρέπει πρόσβαση σε καταχωρίσεις άλλων χρηστών από σχεδιασμό. Αντίθετα, η ViewProperty απαιτεί user_properties σύνδεση. Η διαφορά δεν πρέπει να αντιμετωπίζεται ως αυθαίρετη παράκαμψη εξουσιοδότησης. Παρ’ όλα αυτά, το τρέχον browse predicate δεν εφαρμόζει το is_published της σχέσης χρήστη. Επομένως η αποθήκευση false κατά την προσθήκη δεν εγγυάται απόκρυψη της καταχώρισης από την αγορά. Η πολιτική δημοσίευσης παραμένει ζήτημα προς οριστικοποίηση.

## 9.5 Προσθήκη και λεπτομέρειες χαρτοφυλακίου
Η φόρμα AddProperty συγκεντρώνει τύπο κατοικίας, επιφάνεια, κατασκευή, ανακαίνιση, όροφο, παροχές και προαιρετική asking ανά τ.μ. Η επιλεγμένη διεύθυνση συνοδεύεται από provider στοιχεία. Η υποβολή αποστέλλει JSON και περιμένει έως δύο λεπτά. Με επιτυχία χρησιμοποιεί το επιστρεφόμενο UID για owner detail. Δεν δημιουργεί το UID στον browser ούτε θεωρεί τη δική της επιτυχία υποβολής απόδειξη ολοκλήρωσης χωρίς HTTP απάντηση.

Σε αβέβαιη αποτυχία, όπως timeout μετά από commit, εμφανίζεται σύσταση ελέγχου του Portfolio πριν από επανάληψη. Δεν υπάρχει idempotency key που να καθιστά ασφαλές ένα αυτόματο δεύτερο POST. Η επιλογή αυτή αναγνωρίζει το πραγματικό όριο συναλλακτικότητας του backend. Μια πιο σύνθετη ανθεκτική ροή θα απαιτούσε ξεχωριστές καταστάσεις pending/ready/failed και επαναλήψεις παράγωγης επεξεργασίας πάνω στο ίδιο UID.

Η σελίδα λεπτομερειών διαχωρίζει signed contribution, local importance και global importance. Το θετικό πρόσημο δηλώνει αύξηση της μοντελοποιημένης τιμής σε σχέση με τη baseline, όχι ότι το χαρακτηριστικό είναι αντικειμενικά «καλό». Οι τιμές και τα κείμενα πρέπει να διαβάζονται μαζί με transaction και μονάδα. Μια μικρή απόκλιση αθροίσματος εμφανίζεται ως διαγνωστική πληροφορία, όχι ως ποσοστό σφάλματος της εκτίμησης στην πραγματική αγορά.

## 9.6 Analysis και καταστάσεις αποτυχίας
Η Analysis ξεκινά μόνο αφού επιλεγεί πραγματική περιοχή. Κατά την αναμονή ενημερώνει ότι δημιουργούνται ομάδες και τοπικά μοντέλα. Το Stop waiting ακυρώνει την αναμονή του browser και επισημαίνει ότι η εργασία backend μπορεί να συνεχίζει. Με επιτυχία αποθηκεύονται μαζί αποτέλεσμα και όνομα περιοχής, ώστε η επικεφαλίδα να αναφέρεται στην περιοχή που όντως αναλύθηκε και όχι σε νεότερο κείμενο του input.

Τα components αποτελεσμάτων εμφανίζουν σύνοψη, clusters, περιγραφικά διαγράμματα, ακραίες καταχωρίσεις, αναφορές sell/rent, importance, ζεύγη αλληλεπιδράσεων και παραδείγματα SHAP. Δεν κατασκευάζουν γεωγραφικά polygons για τις ομάδες. Αν ένα μοντέλο λείπει αλλά υπάρχουν clusters, οι warnings επιτρέπουν μερική χρήσιμη προβολή. Η κενή περιοχή διακρίνεται από HTTP αποτυχία, γιατί η απουσία δεδομένων είναι νόμιμο αποτέλεσμα αναζήτησης.

Η απλή αρχιτεκτονική της διεπαφής αποφεύγει επιπλέον libraries για κάθε γράφημα, αλλά έχει κόστος συντήρησης των χειροποίητων components. Οι κοινές HTTP helpers, η επαναχρησιμοποίηση PropertyCard/PropertyDetail και οι δοκιμές συμπεριφοράς μειώνουν τον διπλασιασμό. Η αξιολόγηση στο επόμενο κεφάλαιο εξετάζει τι ελέγχεται αυτοματοποιημένα, χωρίς να εξισώνει τα mock requests με πραγματική λειτουργία όλων των υπηρεσιών.
